# ClutchBids API Documentation

## Overview
ClutchBids is a car listing and auction platform API built with .NET 10. This documentation provides comprehensive details about all available endpoints, their inputs, outputs, and functionality.

**Base URL:** `https://api.clutchbids.com/api/`

## Authentication Endpoints

### Base Path: `/api/auth`

#### 1. Login
**Endpoint:** `POST /api/auth/login`

**Authentication:** None (Public)

**Description:** Authenticates a user and returns access and refresh tokens.

**Request Body:**
```json
{
  "email": "user@example.com",
  "password": "securePassword123"
}
```

**Response (200 OK):**
```json
{
  "success": true,
  "message": "Login successful",
  "data": {
    "id": 1,
    "email": "user@example.com",
    "fullName": "John Doe",
    "accessToken": "eyJhbGciOiJIUzI1NiIs...",
    "refreshToken": "eyJhbGciOiJIUzI1NiIs...",
    "role": "User"
  }
}
```

**Error Response (401 Unauthorized):**
```json
{
  "success": false,
  "message": "Invalid credentials"
}
```

---

#### 2. Register
**Endpoint:** `POST /api/auth/register`

**Authentication:** None (Public)

**Description:** Creates a new user account. The user must verify their email after registration.

**Request Body:**
```json
{
  "email": "newuser@example.com",
  "password": "securePassword123",
  "fullName": "John Doe",
  "phoneNumber": "+1234567890"
}
```

**Response (201 Created):**
```json
{
  "success": true,
  "message": "Registration successful. Please verify your email.",
  "data": {
    "id": 1,
    "email": "newuser@example.com",
    "fullName": "John Doe",
    "role": "User"
  }
}
```

**Error Response (400 Bad Request):**
```json
{
  "success": false,
  "message": "Email already exists"
}
```

---

#### 3. Verify Email
**Endpoint:** `POST /api/auth/verify-email`

**Authentication:** None (Public)

**Description:** Verifies user email using a token sent to their email address.

**Query Parameters:**
- `email` (string, required): User email address
- `token` (string, required): Verification token from email

**Response (200 OK):**
```json
{
  "message": "Email verified successfully"
}
```

**Error Response (400 Bad Request):**
```json
{
  "message": "Invalid or expired verification token"
}
```

---

#### 4. Forgot Password
**Endpoint:** `POST /api/auth/forgot-password`

**Authentication:** None (Public)

**Description:** Sends a password reset link to the user's email address.

**Request Body:**



## Car Listings Endpoints

### Base Path: `/api/carlistings`

#### 1. Search Listings
**Endpoint:** `GET /api/carlistings/search`

**Authentication:** None (Public)

**Description:** Searches car listings with optional filters. Returns different data based on authentication status.

**Query Parameters:**
- `make` (string, optional): Car manufacturer (e.g., "Toyota")
- `model` (string, optional): Car model (e.g., "Camry")
- `year` (int, optional): Manufacturing year
- `minPrice` (decimal, optional): Minimum price
- `maxPrice` (decimal, optional): Maximum price
- `mileage` (int, optional): Maximum mileage
- `location` (string, optional): Location/city
- `status` (string, optional): Listing status (Active, Pending, etc.)
- `pageNumber` (int, optional, default: 1): Page number for pagination
- `pageSize` (int, optional, default: 10): Items per page

**Response (200 OK):**
```json
{
  "success": true,
  "data": {
    "items": [
      {
        "id": 1,
        "title": "2020 Toyota Camry",
        "make": "Toyota",
        "model": "Camry",
        "year": 2020,
        "price": 15000,
        "mileage": 45000,
        "location": "New York",
        "images": ["url1", "url2"],
        "description": "Excellent condition",
        "status": "Active"
      }
    ],
    "totalCount": 100,
    "pageNumber": 1,
    "pageSize": 10
  }
}
```

## Price Offers Endpoints

### Base Path: `/api/priceoffers`

#### 1. Create Offer
**Endpoint:** `POST /api/priceoffers/create`

**Authentication:** Required (Roles: User, Admin, SuperAdmin)

**Description:** Buyer creates a price offer on a car listing.

**Request Body:**
```json
{
  "listingId": 1,
  "offerPrice": 14000,
  "message": "I'm interested in this car. Would you accept this price?"
}
```

**Response (201 Created):**
```json
{
  "id": 1,
  "listingId": 1,
  "buyerId": 2,
  "offerPrice": 14000,
  "originalPrice": 15000,
  "status": "Pending",
  "message": "I'm interested in this car. Would you accept this price?",
  "createdDate": "2024-01-20"
}
```

**Error Response (400 Bad Request):**
```json
{
  "message": "Failed to create offer"
}
```

---

#### 2. Get Offer Details
**Endpoint:** `GET /api/priceoffers/{id}`

**Authentication:** Required (Roles: User, Admin, SuperAdmin)

**Description:** Retrieves details of a specific price offer.

**Path Parameters:**

#### 3. Accept Offer

```json
{
```

```json
  "action": 1,
  "notes": "User has been warned about suspicious activity"
}
```

**Action Codes:**
- `0` = Dismiss
- `1` = Warn User
- `2` = Suspend User

**Response (200 OK):**
```json
{
  "message": "Report reviewed and actioned successfully"
}
```

## Authentication & Authorization

### Authentication Methods
- **Bearer Token (JWT):** All protected endpoints require a JWT token in the Authorization header
  ```
  Authorization: Bearer <accessToken>
  ```

### User Roles
1. **User:** Standard car seller/buyer
2. **Admin:** Can approve listings, verify users, manage reports, assign listing codes
3. **SuperAdmin:** Full system access, can create/remove admins, manage all configurations

### Token Refresh
When access token expires, use the `refresh-token` endpoint to get a new token using your refresh token.

## Best Practices for Frontend Development

### Authentication Flow
1. User registers via `/api/auth/register`
2. User receives email with verification link
3. User verifies email via `/api/auth/verify-email`
4. User logs in via `/api/auth/login` and receives tokens
5. Use access token for subsequent requests
6. Refresh token when access token expires

### Data Pagination
- Implement pagination for list endpoints (e.g., car listings search)
- Use `pageNumber` and `pageSize` query parameters

### File Uploads
- When uploading files (ID documents, sale proof, etc.), use multipart/form-data
- Validate file types on frontend before sending

### Real-time Chat
- Consider implementing WebSocket for real-time chat messaging
- Poll `/api/chats/my-chats` periodically to check for new messages

### Error Handling
- Always check `success` flag in responses
- Display user-friendly error messages from the `message` field
- Handle token expiration and redirect to login when necessary

---

## Rate Limiting & Performance

- API endpoints are designed to handle reasonable request volumes
- Implement pagination for list endpoints to avoid large data transfers
- Cache static data where appropriate on the frontend
